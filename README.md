# 对位实验室 · 双声部约束搜索

给定一段**定旋律**（cantus firmus）和一组**有限的、可勾选的风格规则**，搜索另外两条对位声部。
工具做的是真正的约束搜索与规则解释，不是把定旋律整体平移，也不调用任何曲库或预置作品。

> 规则范围是明确列出的。工具不会声称能“自动生成任何风格的完美音乐”；它求解的是你勾选的那套规则。

```bash
npm install

# 浏览器打开 http://localhost:5173/
```

| 左栏「规则范围」 | 勾选/取消每条规则；切换跨小节历史策略；规则右侧显示本次搜索中该规则触发的剪枝次数 |
| 中栏「可编辑乐谱」 | 三声部纵向对齐谱；拖动音符上下改音高、左右改起始；点击音符查看该时刻 |

| 中栏「搜索结果」 | 可选解列表、每个解的逐音与违例、**搜索剪枝**分布与轨迹、**历史策略对比** |
| 右栏「逐时刻检查」 | 违例列表（点击定位）、逐时刻纵向音程表、可解释不协和（经过/辅助/延留）的说明 |

中的搜索实现；结果区的音符、违例、统计与试听全部来自这次真实搜索，没有任何固定数据冒充。

## 搜索算法

1. **节奏槽**：定旋律按给定音符；两条对位声部按时值预设（固定/模式/跟随定旋律）切成槽位，
   允许跨小节与切分。
2. **事件化深度优先**：所有槽位按起始时间排序，同一时刻先中声部后高声部。每个候选音先做
   即时剪枝（复用最终校验的 `checkSlot`），通过后再考虑延留义务。
3. **候选排序**：优先级进、优先不完全协和、惩罚大跳，使前几个解可听性较好。
4. **终止条件**：达到解上限 / 节点上限 / 时间预算上限。命中后明确报告“被截断，不代表无解”。
5. **完整校验**：每条候选解在记录前再跑一次 `analyzeAssignment`（包含终止纯音程与延留解决），
   只有零错误的解才进入结果。

### 纵向约束按实际重叠区间检查

`src/core/analyze.ts` 的 `slicesBetween` 枚举所有发声起止点，把时间轴切成 `[t, next)` 区间；
每个区间内取各声部**实际在响**的音，两两计算音程。绝不是比较音符数组的相同下标。

内置演示例 `overlap-misalignment` 专门展示这一点：三个声部时值错位后，
按实际重叠查出 2 处不协和，而按数组同下标配对看到 0 处（界面右栏会显示该对比）。

### 不协和的上下文判定

不协和**不会**被一律排除。`classifyDissonance` 会区分：

- **经过音**：弱位上，一个声部级进进入、同向级进离开不协和音；
- **辅助音**：弱位上，级进到不协和音后级进返回；
- **延留音**：一个音在片段开始前已在响，被另一声部进入撞成不协和，并在结束时下行级进解决；
- **无法解释**：以上都不成立，才会在强拍触发「强拍纵向协和」。

界面的「可解释的不协和」列表会给出每种情况的文字依据（哪个音、被谁撞入、在哪里解决）。

### 跨小节历史：保留 vs 截短

搜索在**事件边界**推进历史。判定一个音是否“被撞成延留”时，需要知道它在片段开始前是否已在响，
以及它是否负有“必须下行级进解决”的义务。

- **保留悬挂义务（carry）**：跨小节的预备与未完成义务一起带入下一步，平行/直接音程也跨小节比较。
- **截短到本小节（truncate）**：进入新小节时丢弃此前的纵向预备与未完成义务，只看本小节。

「历史策略对比」把两种搜索找到的解**取并集**，再用两种策略各自完整复核同一份乐谱，
因此“仅一种历史成立”的差异来自跨小节判决本身，而不是枚举顺序。
内置对比例 `cross-bar-suspension` 会产生这类差异（界面与 CLI 都会列出具体条数）。

### 横向规则

每条声部独立满足：音域、调内音、最大跳进、禁三全音、跳进后反向级进恢复、禁同音重复。
这些规则与纵向规则在同一 `checkSlot` 中判定，搜索剪枝与最终解释完全一致。

## 规则清单

| 类别 | 规则 |
| --- | --- |
| 纵向 | 强拍纵向协和、允许经过音、允许辅助音、允许延留音、延留音下行解决、纯四度视为协和、禁止平行五/八度、禁止直接五/八度、禁止声部交错 |
| 横向 | 最大旋律跳进、禁止三全音跳进、跳进后反向级进恢复、禁止同音重复、只使用调内音 |
| 起止 | 起始用纯音程、终止于主音、终止纵向纯音程 |

约定：定旋律作为**最低声部**；对位 I 在其上方，对位 II 再上方。小调采用和声小调（含升七级）。
调内音过滤默认开启，因此搜索出的音都在所选调式内；非调内音仅可能来自手动编辑，并会被诊断为错误。

## 内置谱例

| id | 类型 | 展示内容 |
| --- | --- | --- |
| `feasible` | 可行 | 默认规则下有多条解，含经过音、辅助音与可选解差异 |
| `parallel-fifth` | 矛盾 | C3/G4 → D3/A4 平行五度 |
| `unresolved-suspension` | 矛盾 | 延留音 A4 应下行到 G4，却上行到 B4 |
| `leap-recovery` | 矛盾 | E4→A4 跳进后继续上行到 B4 |
| `voice-crossing` | 矛盾 | 对位 I 低于定旋律 |
| `overlap-misalignment` | 演示 | 下标对齐会漏掉错位不协和 |
| `cross-bar-suspension` | 对比 | 跨小节悬挂义务改变解集 |

## 测试与构建

```bash
npm test          # vitest：核心规则、重叠区间、上下文判定、搜索、历史对比
npm run build     # tsc --noEmit + vite build
```

测试覆盖的关键断言：

- 实际重叠检查能发现同下标配对漏掉的不协和；
- 经过音/辅助音被解释，而不是被强拍规则直接判错；
- 搜索结果不是定旋律的平移（相邻音偏移量不唯一）；
- 规则冲突时返回“无解”，不伪造解；
- 跨小节历史策略产生“仅一种策略成立”的解。
